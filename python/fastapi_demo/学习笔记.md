## 1. Python 环境管理命令（conda）

### 问题
```bash
# 1、创建工程文件夹 fastapi_demo
# 2、创建虚拟环境
conda create -n web python=3.13

# 3、激活虚拟环境
conda activate web
```
这些命令的实际作用是什么？

### 解答

#### `conda create -n web python=3.13`
- `conda`：Python 的包/环境管理器，类似 Maven/Gradle + SDKMAN 的结合体
- `create -n web`：创建一个名为 `web` 的隔离环境
- `python=3.13`：指定在这个环境中安装 Python 3.13 版本

**Java 类比**：相当于 `sdk install java 17.0.5-tem` 并给这个 JDK 版本标记为某个项目专用。

#### `conda activate web`
**Java 类比**：相当于切换 `JAVA_HOME` 环境变量：
```bash
export JAVA_HOME=/path/to/jdk17
export PATH=$JAVA_HOME/bin:$PATH
```

### 核心概念对比

| Python (conda) | Java 类比 |
|---|---|
| conda 环境 | 独立的 JDK 安装 + 独立的 classpath |
| `conda create -n web` | 安装一个全新的 JDK 并命名 |
| `conda activate web` | 切换 JAVA_HOME 到这个 JDK |
| `pip install xxx` | 在 pom.xml 添加 dependency |
| 虚拟环境 | 类似给每个项目配独立的 JDK + Maven 本地仓库 |

### 为什么 Python 需要虚拟环境？
Java 通过 Maven/Gradle 管理依赖，每个项目的 jar 包下载到本地仓库（`~/.m2`），编译时通过 classpath 隔离。但 Python 的包是全局安装的（默认装到系统 Python 的 `site-packages` 目录），如果不隔离，不同项目会互相冲突。

所以 Python 用虚拟环境给每个项目一个**独立的 Python 解释器 + 独立的包安装目录**，效果类似 Java 中每个项目有自己的 `.m2/repository`。

## 2. `__init__.py` 是什么？为什么每个文件夹都有？

### 作用
告诉 Python 解释器"这个文件夹是一个 Python 包（package），可以 `import`"。

**Java 类比**：Java 的包声明 `package com.example.service;` 是写在每个 `.java` 文件开头的。Python 没有这个语法，而是通过 `__init__.py` 文件来标记文件夹是一个包。

### 对比

```
Java:                          Python:
src/main/java/                 app/
  com/example/                   services/
    service/                       __init__.py    ← 标记这是包
      ContractService.java         contract_service.py
```

### 是否必须？

| Python 版本 | 是否必须 |
|---|---|
| Python 3.3 之前 | **必须**，没有就无法 import |
| Python 3.3+ | 不必须，但强烈建议保留 |

### 新建文件夹时要不要加？

| 场景 | 需要 `__init__.py`？ |
|---|---|
| 新建要被 `import` 的包（如 `app/services/xxx/`） | ✅ 需要 |
| 纯资源目录（如 `static/`, `templates/`, `uploads/`） | ❌ 不需要 |
| 测试目录 `tests/` | ✅ 建议加 |
| 项目根目录 | ❌ 不需要 |

**简单规则**：只要文件夹里有 `.py` 文件可能被其他文件 `import`，就加 `__init__.py`。

### `__init__.py` 进阶用法
除了空文件标记包，还可以写代码控制包的导入行为：
```python
# app/services/__init__.py
from .contract_service import ContractService
# 这样外部可以直接: from app.services import ContractService
# 而不是: from app.services.contract_service import ContractService
```

## 3. pip 安装包报错：[WinError 32] 文件被占用 / 下载超时

### 问题
```
Downloading fastar-0.11.0-cp314-cp314-win_amd64.whl (486 kB)
WARNING: Connection timed out while downloading.
ERROR: Could not install packages due to an OSError: [WinError 32] 另一个程序正在使用此文件，进程无法访问。
```

### 原因
1. **Connection timed out**：网络不稳定或 PyPI 官方源在国外，下载慢导致超时
2. **[WinError 32]**：Windows 文件被占用，常见原因：
   - 杀毒软件/Windows Defender 正在扫描下载的 `.whl` 临时文件
   - 上次失败的下载未释放文件句柄

**Java 类比**：相当于 Maven 从 Maven Central 下载 jar 包超时，或者本地 `.m2/repository` 中的文件被锁定。

### 解决方法

#### 方法一：换国内镜像源（最推荐）
```bash
pip install fastapi uvicorn -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
```

#### 方法二：设置超时 + 镜像源
```bash
pip install fastapi uvicorn -i https://mirrors.aliyun.com/pypi/simple/ --default-timeout=100 --trusted-host mirrors.aliyun.com
```

#### 方法三：清理临时文件后重试
```bash
# 删除 pip 缓存和临时文件
pip cache purge
rd /s /q %TEMP%\pip-* 2>nul
# 然后重新安装
pip install fastapi uvicorn
```

#### 方法四：永久配置镜像源（一劳永逸）
```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config set global.trusted-host pypi.tuna.tsinghua.edu.cn
```

**Java 类比**：相当于在 Maven `settings.xml` 里配置阿里云镜像仓库，避免从 Maven Central 下载 jar 包时超时。

### 国内常用 PyPI 镜像源

| 镜像源 | URL |
|---|---|
| 清华 | `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 阿里云 | `https://mirrors.aliyun.com/pypi/simple/` |

## 4. FastAPI 代码组织：拆分成多个文件 vs 全写 main.py

### 两种方式

| 方式 | 描述 | Java 类比 |
|---|---|---|
| A：拆分文件 | 路由、Service、DTO、异常处理各自独立文件 | 标准 Spring Boot 分层 |
| B：全写 main.py | 所有代码塞一个文件 | 所有代码写在一个 `main()` 方法里 |

### 对比

| 维度 | 方式 A：拆分 | 方式 B：全写 main.py |
|---|---|---|
| 可读性 | ✅ 每个文件职责单一 | ❌ 几百行混在一起 |
| 可维护性 | ✅ 改合同只动 contract.py | ❌ 牵一发动全身 |
| 团队协作 | ✅ 不冲突，各自改各自的文件 | ❌ 天天 merge conflict |
| 复用性 | ✅ Service 可被多处复用 | ❌ 逻辑嵌在路由里无法复用 |
| 测试 | ✅ 可单独测 Service | ❌ 只能测 HTTP |
| 适合场景 | 正经项目、多人协作 | 原型验证、<100 行脚本 |

### 结论
有多模块的项目（如合同 + LLM），**必须用拆分方式**。`main.py` 的职责是**组装**（注册路由、中间件、异常处理），类似 Spring 的 `@Configuration` 类。

### 请求处理链路（拆分方式）
```
请求 → middleware（日志/认证）
     → api/v1/contract.py（路由层，接收参数）
     → schemas/request.py（Pydantic 自动校验入参）
     → services/contract_service.py（业务逻辑）
     → services/llm_service.py（调用大模型）
     → schemas/response.py（封装响应）
     → exceptions/handlers.py（兜底异常）
     → 响应返回
```

## 5. FastAPI 代码组织风格对比：模块内聚 vs 统一分层

### 别人的写法（模块内聚 / DDD 风格）
```python
from src.modules.permission.schema import PermissionCreate, PermissionRead
from src.modules.permission.service import PermissionService

@router.get("/{id}", response_model=ResponseSchema[PermissionRead])
async def get_permission(id: int, service: PermissionService = Depends(get_permission_service)):
    ...
```

**Java 类比**：DDD 分包 + `@Autowired` 依赖注入

特点：
- 每个模块（permission/user）独立一个文件夹，包含自己的 schema、service、api
- 使用 `Depends` 做依赖注入（类似 Spring `@Autowired`）
- 使用 `ResponseSchema[T]` 泛型包装响应（类似 Java 泛型）

### 你的当前架构（统一分层 / MVC 风格）
```
app/
  api/v1/contract.py       ← 所有路由
  schemas/request.py        ← 所有请求 DTO
  schemas/response.py       ← 所有响应 DTO
  services/contract_service.py
```

**Java 类比**：传统 Spring MVC 分包（controller 一堆、service 一堆、dto 一堆）

特点：
- 按层分包，同一层的所有模块放一起
- 不使用 `Depends`，手动调用 Service
- 不使用泛型响应，手动构建 dict

### 对比

| 维度 | 模块内聚（别人） | 统一分层（你） |
|---|---|---|
| 小项目 (<5 模块) | 稍过度 | ✅ 简单够用 |
| 大项目 | ✅ 模块独立不冲突 | ❌ schemas 文件会膨胀 |
| 依赖注入 | `Depends` 注入 | 手动 new / 导入 |
| Java 习惯 | 类似 DDD | 类似传统 MVC |

### 建议
你当前 2 个模块（合同 + LLM），统一分层完全够用。但可以做一个小优化：**按模块拆分 DTO 文件**，避免单文件膨胀：

```
schemas/
  contract.py    # 合同专属 DTO
  llm.py         # LLM 专属 DTO
  common.py      # 公共 DTO（BaseResponse, PageResponse）
```

### FastAPI `Depends` 依赖注入 vs 手动调用

| | `Depends` 注入 | 手动 new/导入 |
|---|---|---|
| Java 类比 | `@Autowired` | `new XxxService()` |
| 优点 | 自动管理生命周期、方便测试 mock | 简单直观、无魔法 |
| 缺点 | 学习成本、链式依赖难追踪 | 无法自动管理 DB session |
| 适合 | 有数据库的项目 | 简单服务 |

**结论**：如果你后续要接数据库（SQLAlchemy），建议引入 `Depends` 管理 DB session。如果只是调用大模型 API，手动调用就够了。

## 6. `dict` vs Pydantic `BaseModel` 对比

### `dict` — Python 内置字典

```python
# 创建
data = {"id": 1, "title": "软件开发合同", "status": "draft"}

# 取值
print(data["title"])        # 软件开发合同
print(data.get("xxx", ""))  # 安全取值，不存在返回默认值

# 赋值
data["status"] = "signed"
data["new_field"] = "随意加"  # 可以任意添加字段，无约束
```

**特点**：灵活、无类型约束、无校验、IDE 无法提示。

**Java 类比**：`Map<String, Object>`，取值需要强转，没有编译期保障。

---

### `BaseModel` — Pydantic 数据模型

```python
from pydantic import BaseModel, Field
from typing import Optional

class ContractResponse(BaseModel):
    '''合同详情响应'''
    id: int
    title: str
    content: str
    party_a: str
    party_b: str
    status: str = "draft"           # 有默认值
    created_at: Optional[str] = None  # 可选字段

# 使用
contract = ContractResponse(
    id=1, title="合同", content="...",
    party_a="甲方", party_b="乙方", status="signed"
)

print(contract.title)        # IDE 有智能提示
print(contract.model_dump()) # 转为 dict
```

**特点**：强类型、自动校验、IDE 智能提示、自动生成 JSON Schema。

**Java 类比**：Java 的 DTO/VO 类（`class ContractResponse { private int id; private String title; ... }`），编译期就知道有哪些字段和类型。

---

### 核心对比表

| 维度 | `dict` | `BaseModel` |
|------|--------|-------------|
| Java 类比 | `Map<String, Object>` | DTO/VO 类 |
| 类型约束 | 无，随便放什么 | 强类型，声明什么就是什么 |
| 数据校验 | 无，手动 if-else | 自动校验，如 `ge=1, le=100` |
| 默认值 | 手动 `.get("key", default)` | 声明时直接写 `= 默认值` |
| IDE 提示 | 无，靠记忆 | 点号自动补全所有字段 |
| JSON 互转 | `json.dumps(d)` | `.model_dump_json()` / `.model_validate()` |
| 字段别名 | 不支持 | `Field(alias="partyA")` 自动映射 |
| 嵌套模型 | 手动嵌套 dict | 直接声明子 BaseModel，自动嵌套校验 |
| OpenAPI 文档 | 无法自动生成 | FastAPI 自动生成 Swagger 文档 |
| 运行时性能 | 快（原生类型） | 略慢（有校验开销，但可忽略） |

---

### 在 FastAPI 中的体现

```python
# ❌ dict 方式 — 无校验，Swagger 文档空白
@app.post("/create")
async def create(data: dict):
    title = data.get("title", "")  # 没校验，啥都可能
    ...

# ✅ BaseModel 方式 — 自动校验 + Swagger 文档自动生成
@app.post("/create")
async def create(data: ContractCreateRequest):
    title = data.title  # 类型安全，IDE 有提示
    ...
```

FastAPI 会根据 `BaseModel` 的字段定义**自动生成 Swagger 文档**，包含字段类型、是否必填、描述、约束条件等。用 `dict` 则文档一片空白。

---

### 常用 Pydantic 字段约束 (`Field`)

| 参数 | 说明 | 示例 |
|------|------|------|
| `...` | 必填字段 | `title: str = Field(...)` |
| `default` | 默认值 | `status: str = Field(default="draft")` |
| `alias` | JSON 字段别名 | `Field(alias="partyA")` |
| `min_length` / `max_length` | 字符串长度限制 | `Field(min_length=1, max_length=200)` |
| `ge` / `le` | 数值大小限制 | `Field(ge=1, le=100)` |
| `description` | 字段描述（显示在 Swagger） | `Field(description="合同标题")` |
| `pattern` | 正则校验 | `Field(pattern=r"^\d{4}-\d{2}-\d{2}$")` |

---

### 常用 Pydantic 方法

```python
# dict → BaseModel
contract = ContractResponse.model_validate({"id": 1, "title": "合同", ...})

# BaseModel → dict
d = contract.model_dump()

# BaseModel → JSON 字符串
json_str = contract.model_dump_json()

# 部分更新（只更新传入的字段）
contract = existing_contract.model_copy(update={"status": "signed"})
```

---

### 一句话总结

> **`dict` = 裸数据容器，灵活但无保障；`BaseModel` = 带类型契约的数据模型，像 Java 的 DTO，编译期/运行时都有保障。在 FastAPI 项目中，请求体和响应体一律用 `BaseModel`，内部临时数据用 `dict`。**

## 7. Python 创建类的三种方式：普通 class / dataclass / BaseModel

### 对比

```python
# 1. 普通 class（纯 Python，不用任何库）
class ContractA:
    def __init__(self, id: int, title: str, status: str = "draft"):
        self.id = id
        self.title = title
        self.status = status

c = ContractA(1, "合同", "signed")
print(c.title)  # IDE 没提示

# 2. dataclass（Python 3.7+ 内置，轻量级）
from dataclasses import dataclass

@dataclass
class ContractB:
    id: int
    title: str
    status: str = "draft"

c = ContractB(id=1, title="合同", status="signed")
print(c.title)  # 有类型声明，IDE 有提示

# 3. BaseModel（Pydantic，重量级，带校验）
from pydantic import BaseModel

class ContractC(BaseModel):
    id: int
    title: str
    status: str = "draft"

c = ContractC(id=1, title="合同", status="signed")
print(c.title)  # 有类型声明 + 自动校验 + JSON 互转
```

### 核心区别

| | 普通 `class` | `@dataclass` | `BaseModel` |
|---|---|---|---|
| 类型校验 | ❌ 无 | ❌ 无 | ✅ 自动 |
| JSON ↔ 对象互转 | ❌ 手动 | ❌ 手动 | ✅ `.model_validate()` / `.model_dump()` |
| Swagger 文档 | ❌ 无法 | ❌ 无法 | ✅ FastAPI 自动生成 |
| IDE 提示 | ❌ 弱 | ✅ 有 | ✅ 有 |
| 性能 | 最快 | 快 | 稍慢（校验开销） |

### 一句话

> **写 FastAPI 接口的请求/响应体必须用 `BaseModel`**（否则 Swagger 文档和自动校验都没了）。内部工具类、普通对象用 `@dataclass` 或普通 `class` 完全没问题。

## 8. FastAPI 路由注册机制：`@app.get()` vs `@router.get()` + `include_router`

### 两种写法都能处理请求

```python
# 方式 1：全写 main.py，用 @app
@app.get("/contract/list")
async def list_contracts():
    ...

# 方式 2：分文件，用 @router + include_router
# contract.py
router = APIRouter()

@router.get("/list")
async def list_contracts():
    ...
```

**`@app.get()` 和 `@router.get()` 功能完全一样**，区别只是 `router` 可以拆分到不同文件，最后统一注册到 `app`。

### 路由注册链路

```
启动命令: uvicorn app.main:app
              │
              ▼
         main.py
         app = FastAPI()                          ← 唯一的 app 实例
         app.include_router(api_router, prefix="/api/v1")
              │
              │  把 api_router 挂到 app 上，加前缀 /api/v1
              ▼
         router.py
         api_router = APIRouter()                 ← 汇总所有子路由
         api_router.include_router(contract_router, prefix="/contract")
         api_router.include_router(llm_router, prefix="/llm")
              │                    │
              │  加前缀 /contract  │  加前缀 /llm
              ▼                    ▼
         contract.py            llm.py
         router = APIRouter()   router = APIRouter()
         @router.get("/list")   @router.post("/chat")
```

**路径拼接**：

```
/api/v1  +  /contract  +  /list  =  /api/v1/contract/list
  ↑           ↑             ↑
main.py    router.py    contract.py
```

### Java 类比

| Python | Java |
|--------|------|
| `main.py` 的 `app = FastAPI()` | `SpringApplication`（唯一） |
| `router.py` 的 `api_router` | 统一前缀配置 `/api/v1` |
| `contract.py` 的 `router = APIRouter()` | `@RestController` + `@RequestMapping("/contract")` |
| `@router.get("/list")` | `@GetMapping("/list")` |
| `app.include_router(...)` | 自动扫描 `@RestController` 并注册 |

### `router.py` 有什么用？

**集中管理所有子路由的前缀和标签**，避免 `main.py` 里堆太多 `include_router`。

```python
# ❌ 没有 router.py，main.py 会很乱
app.include_router(contract_router, prefix="/api/v1/contract", tags=["合同管理"])
app.include_router(llm_router, prefix="/api/v1/llm", tags=["大模型"])
app.include_router(user_router, prefix="/api/v1/user", tags=["用户管理"])
# 前缀 /api/v1 重复 N 次

# ✅ 有 router.py，main.py 只需一行
app.include_router(api_router, prefix="/api/v1")

# router.py 里集中管理
api_router.include_router(contract_router, prefix="/contract", tags=["合同管理"])
api_router.include_router(llm_router, prefix="/llm", tags=["大模型"])
```

### 关键点

- **整个项目只有一个 `app = FastAPI()`**，在 `main.py` 里，不能删
- 其他文件用 `router = APIRouter()`，可以有很多个
- 请求体用法完全一样：`async def create(data: ContractCreateRequest)`，无论 `@app` 还是 `@router`，BaseModel 自动接收 JSON body
- `main.py` 只做注册，不写具体接口逻辑
